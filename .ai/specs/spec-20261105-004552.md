### 1-3 ソースで確かめた前提

調べた対象: `arrow-code-lab/which-level` の最新作業ツリー（branch `feature/7-find-screen-ui`、e4e9d5c。`origin/main` 73800b1 を含む）。

- **アプリ**: Flutter 製、Android・iOS 共通コード。表示名「何階だっけ」/ "Which Level?"。applicationId・bundle ID はともに `com.arrowcodelab.whichlevel`。Android 10 以上・iOS 17 以上。日本語・英語
- **内容**: 自分の車を停めた場所（位置・階・柱番号・写真・メモ）を記録し、方位矢印・距離・地図で車まで案内する。アプリを開いたときに、時刻と位置を自動で記録する
- **アカウント・自社サーバー**: 無い。データは端末内（SQLite `whichlevel.db`、アプリ専用の `photos/` フォルダ、設定、`purchase_state.json`、地図タイルキャッシュ `tiles/`）にだけ保存する
- **記録の項目**: 緯度・経度・精度、気圧（hPa）とその計測時刻、階・柱・メモ、地名（逆ジオコーディングで取得）、状態・解除時刻・お気に入り、写真から読み取った文字
- **写真**: アプリ内カメラで撮影（音声なし）。長辺 1600px に縮小し、1 件につき 5 枚まで保存。ギャラリーには出ない。写真ライブラリは読まない
- **OCR**: Google ML Kit の日本語モデルを使い、端末内で処理する
- **センサー**: 気圧計、コンパス、振動
- **権限（Android）**: ACCESS_FINE_LOCATION、ACCESS_COARSE_LOCATION、CAMERA、VIBRATE、INTERNET。RECORD_AUDIO と外部ストレージの権限は明示的に外している。AD_ID は AdMob SDK のマニフェストマージで入る見込み（未確定）
- **権限（iOS）**: カメラ、位置情報（使用中のみ）、モーション、一時的な正確な位置（`FindParkedCar`）。ATT・写真ライブラリ・マイク・連絡先・バックグラウンドの権限は無い
- **外部への送信**:
  - OpenStreetMap の地図タイル（tile.openstreetmap.org。User-Agent はアプリ ID）
  - OS の逆ジオコーディング（Android は Google、iOS は Apple に座標を送る）
  - Google AdMob のバナー広告と UMP の同意画面（Android は既定でパーソナライズあり、iOS は非パーソナライズ）
  - ストア課金（Google Play / App Store）とストアの評価画面
  - 外部の地図アプリ（Google マップ / Apple マップ）での経路案内
  - OS の共有シート（座標入りの Google マップ URL・階・柱・時刻を共有）
- **使っていないもの**: Firebase（Analytics・Crashlytics・Auth・FCM 等）、他の解析・クラッシュ収集、プッシュ通知、アカウント
- **課金**: 非消耗型の買い切り「広告なし版」（`ad_free_lifetime`）。広告が消え、履歴が無制限になる（無料版は直近 30 件まで）。購入の復元あり。定期購入は無い。価格は未定
- **保持と削除**: 完了した記録の写真は既定で 90 日後に自動削除（30・90・180・365 日から選べる。お気に入りは残す）。設定の「すべてのデータを削除」で、記録・写真・設定・地図キャッシュを削除する（購入状態は残す）。履歴から 1 件ずつ削除することもできる。Android のバックアップと端末間の移行は無効
- **アプリ内の既存リンク**: ポリシー・規約の URL と問い合わせ先は、まだアプリに無い
- **対象年齢**: 子ども向けではない。年齢確認は無い

参考元: `arrow-code-lab/room-check-pdf-policy` の `ポリシー確認/`（index.html・terms.html・legal.html。日英切替、単体の HTML＋インライン CSS/JS）。

## §2 ゴール

Android と iOS で共通に使える 1 本のポリシー一式をこのリポジトリに置き、両ストアに同じ URL を登録できるようにする。

## §3 要件

- FR-1: room-check-pdf-policy と同じ構成で、`index.html`（プライバシーポリシー）、`terms.html`（利用規約）、`legal.html`（特定商取引法に基づく表記）の 3 ページを作る。置き場所はリポジトリ直下とする（GitHub Pages で公開しやすいため。参考元はリポジトリ直下とサブフォルダの両方に置いている）
- FR-2: 各ページを日本語と英語で切り替えられるようにする。見た目と切替の仕組みは参考元に合わせる。外部 CDN は使わない
- FR-3: プライバシーポリシーは参考元の章立て（適用範囲とアプリ情報 / 取り扱う情報 / 端末の権限 / 第三者サービス / 保存場所と保持期間 / 第三者提供 / 利用者の権利 / 子ども / 準拠法 / 改定 / お問い合わせ）に沿って、1-3 の事実で書く
- FR-4: OS ごとに違う点は、同じ章の中で「Android」「iOS」と並べて書く
- FR-5: 利用規約には、買い切り課金（広告なし版）、購入の復元、広告の表示、免責（位置・階の判定精度、案内結果）、地図データの出典（© OpenStreetMap contributors）を書く
- FR-6: 特商法の表記は、参考元の形をもとに、買い切りの非消耗型として書く（自動更新・解約の行は削り、復元の方法を書く）。支払方法は Google Play / App Store とする
- FR-7: 運営者と連絡先、提供地域、価格の表記は §1-1 の回答のとおりにする
- FR-8: 3 ページを互いにリンクする

## §4 選ばれた案と確認事項への回答

**案A: 参考元と同じ 3 ページ構成（OS の違いは本文の中で書き分け）**を採用した（その場で回答。AskUserQuestion）。確認事項は無い。

実装後の追加回答（2026-11-05）: 利用規約の賠償の上限は、購入者は「広告なし版」の支払額、無料の利用者は「広告なし版」の販売価格の 2 分の 1 とする。

## §5 棄却した案

- 案B（3 ページ＋ストア申告の対応表）: 公開しない内部資料が増え、アプリを変えるたびに直す所が増える。ストアへの申告は別に行う
- 案C（1 ページにまとめる）: 参考元と構成が揃わず、ストアに登録する URL がアンカー付きになる

## §8 未解決事項

- U-1: 「広告なし版」の価格が決まっていない（表記は購入画面の表示額に任せるので、ページは直さなくてよい）
- U-2: Android で AD_ID 権限が入るかは、ビルドして確かめるまで分からない。ポリシーには「広告 ID を利用する場合がある」と書いておく
- U-3: アプリの設定画面に、ポリシー・利用規約・問い合わせ先へのリンクが無い（App Store の審査ではアプリ内のリンクが求められる）。which-level 側の対応になるので、この作業には含めない
- U-4: iOS の App Store ID がまだ決まっていない
- U-5: 公開 URL（GitHub Pages の有効化）はこの作業に含めない
